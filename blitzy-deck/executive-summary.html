Delivery summary

2048, rebuilt as a roguelike

A twelve-year-old browser game is now a run-based game with relics, a 3D board, and the tests it never had.

01

What we did

Four things shipped

  • Game rules separated from the screen.
  • The board now renders as animated 3D blocks.
  • Sixteen relics, chosen one per stage.
  • Six thousand automated tests.

One change unlocked the rest

  • The rules no longer touch the screen.
  • They announce what happened instead.
  • Anything can listen: 3D, relics, sound.
  • New features stop touching old code.
graph TD R["Game rules"] --> E["Announcement"] E --> V["3D board"] E --> L["Relics"] E --> U["Screens"] E --> O["Monitoring"]

Every listener is independent and optional.

02

Why it matters

Hosting still costs nothing

  • No servers, no databases, no accounts.
  • Deployment stays a folder copy.
  • Nothing to breach, nothing to patch.
  • The same free hosting as before.
graph LR B["One build command"] --> D["Output folder"] D --> H["Any static host"] H --> P["Players"]

The safety net we added

0 Tests before this work
5994 Automated checks now

Every change is now checked before it reaches a player.

03

What changed inside

Before: everything tangled

graph TD S["Ten script files<br/>loaded in a fixed order"] --> C["Rules file"] C -->|"writes directly"| P["Page"] C --> G["Board data"] C --> ST["Saved score"] P --> PL["Player"]

The rules wrote to the page, so neither could change alone.

After: one publisher, many listeners

graph TD I["Keys, touch, buttons"] --> E["Rules engine"] E --> B["Announcement bus"] B --> R["Relics"] B --> T["3D board"] B --> U["Screens and audio"] B --> M["Monitoring"] E --> SV["Saved run"]

The engine holds no reference to the screen. Adding a relic edits nothing.

The board reaches players twice

graph LR B["Board state"] --> C["3D canvas"] B --> A["Readable layer"] C --> P["Sighted play"] A --> S["Screen readers"]
  • Pixels for players who can see them.
  • Spoken labels for players who cannot.
  • Every action reachable by keyboard.
  • Motion can be switched off.

Same seed, same run

graph LR SD["Run seed"] --> S1["Tile values"] SD --> S2["Tile places"] SD --> S3["Relic offers"] S1 --> RUN["Identical replay"] S2 --> RUN S3 --> RUN
  • A seed replays a run exactly.
  • Bugs become reproducible reports.
  • Shareable daily runs become possible later.
  • Seeds are public, and labelled so.

Risks we accepted

Four risks, four answers

Risk Mitigation
3D needs modern hardware Numbered board takes over
Old browsers dropped Deliberate, documented choice
Developers need a build One install, one command
Video can record blank Check fails unless visible

How the team starts

  • Install once with npm install
  • Play locally with npm run dev
  • Ship with npm run build
  • Every choice is written down.
